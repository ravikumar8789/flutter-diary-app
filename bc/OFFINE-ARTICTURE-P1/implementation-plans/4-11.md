# Phase 4.11: Streak Recalc on Entry Save → Sync Queue

**Goal:** When streak is recalculated after entry save (or grace use), add to sync queue instead of calling Supabase directly. SyncWorker pushes when online. No direct batchUpdateStreakData from entry-save path.

**Flow:** Entry save → recalc streak → update local (is_synced=0) → add to sync queue → processSyncQueue (when online) → Supabase.

**Prerequisites:** Phase 3.7 (addStreakToSyncQueue, sync queue schema), 3.9 (SyncWorker processes streak).

## 3. Implementation Steps

### Step 3.1: Replace _scheduleStreakSync with addStreakToSyncQueue

**File:** `lib/services/user_data_service.dart`

**3.1.1** Remove or repurpose `_scheduleStreakSync`:
- Current: debounced timer → batchUpdateStreakData.
- New: call `addStreakToSyncQueue(userId)` immediately (or with debounce for dedupe).

**3.1.2** Add `addStreakToSyncQueue` (from 3-7) if not exists:
```dart
static Future<void> addStreakToSyncQueue(String userId) async {
  final db = await DatabaseManager().database;
  final streak = await db.query('streaks', where: 'user_id = ?', whereArgs: [userId], limit: 1);
  if (streak.isEmpty) return;
  final row = streak.first;
  if ((row['is_synced'] as int? ?? 1) == 1) return;
  // Dedupe: remove existing pending streak item for this user
  await db.delete('sync_queue', where: "entity_type = 'streak' AND entity_id = ?", whereArgs: [userId]);
  await LocalEntryService().addToSyncQueue(
    entityType: 'streak',
    entityId: userId,
    tableName: 'streaks',
    operation: 'upsert',
    data: _streakRowToSyncPayload(row),
  );
}
```

**3.1.3** Replace `_scheduleStreakSync(userId)` with `addStreakToSyncQueue(userId)` in:
- `_persistStreak` (line ~638)
- `_useGraceDayForStreak` (line ~1471)

**3.1.4** Option: keep debounce for addStreakToSyncQueue to avoid rapid duplicate adds (e.g. multiple _persistStreak calls in quick succession). Debounce can still call addStreakToSyncQueue; dedupe in addStreakToSyncQueue (delete existing + insert) handles it.

## 5. Dedupe Strategy

| Approach | Pros | Cons |
|----------|------|------|
| No debounce, dedupe in addStreakToSyncQueue | Simple, latest wins | Multiple queue ops per rapid saves |
| Debounce 3s, then addStreakToSyncQueue | Fewer queue ops | Slight delay before queue |
| Replace existing streak item (delete + insert) | One pending streak per user | Slightly more DB ops |

**Recommended:** Dedupe in addStreakToSyncQueue (delete existing streak item for user_id, then insert). No debounce. Keeps logic simple.
