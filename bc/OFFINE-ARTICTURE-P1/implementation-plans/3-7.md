# Phase 3.7: Extend Sync Queue for Streak, User Profile, User Settings

**Goal:** Extend the sync queue so offline changes to streak, user_profile, and user_settings are queued and synced to Supabase when online. Local-first: write locally → add to queue → process when online.

**Prerequisites:** Phase 1.1 (users, user_settings tables), 1.2, 1.3, 2.4–2.6. Local tables exist; DataFetchService reads from SQLite.

---

## 1. Current State

| Component | Current Behavior |
|-----------|------------------|
| **sync_queue table** | entry_id TEXT NOT NULL, table_name, operation, data. Entry-centric. |
| **SyncWorker.processSyncQueue** | Uses `getUnsyncedEntries()` — entries with is_synced=0. Does NOT read sync_queue. |
| **Entries** | LocalEntryService adds to sync_queue on save; SyncWorker syncs via getUnsyncedEntries. |
| **Streak** | Updated locally (is_synced=0) in UserDataService, GraceSystemService, EntryProvider. No sync queue. Synced via batchUpdateStreakData when called directly. |
| **User profile** | No local write path yet. Fetched from Supabase only. |
| **User settings** | No local write path yet. Fetched from Supabase only. |

---

## 2. Target State

| Entity | Add to Sync Queue When | Supabase Sync Method |
|--------|------------------------|----------------------|
| Streak | Local streaks row updated with is_synced=0 | batchUpdateStreakData RPC |
| User profile | Local users row updated with is_synced=0 | users.upsert |
| User settings | Local user_settings row updated with is_synced=0 | user_settings.upsert |

**Process order:** Entries (existing flow) → streak → user_profile, user_settings (parallel OK).

---

## 3. Schema Extension

### 3.1 Add entity_type and entity_id

**Current:** entry_id required, entry-centric.

**New:** Support user-scoped entities. Add columns:

| Column | Type | Notes |
|--------|------|-------|
| entity_type | TEXT | 'entry' \| 'streak' \| 'user_profile' \| 'user_settings' |
| entity_id | TEXT | For entry: entry.id. For streak/profile/settings: user_id. |

**Migration:** Add entity_type, entity_id. Existing rows: entity_type='entry', entity_id=entry_id. Keep entry_id for backward compat (nullable for non-entry types).

**Simpler option:** Make entry_id nullable. Add entity_type, entity_id. For entries: entity_type='entry', entity_id=entry_id, entry_id=entry_id. For others: entity_type='streak'|'user_profile'|'user_settings', entity_id=user_id, entry_id=NULL or ''.

Future<void> addToSyncQueue({
  required String entityType,
  required String entityId,
  required String tableName,
  required String operation,
  required Map<String, dynamic> data,
}) async {
  final db = await _dbManager.database;

}

### Step 4.4: Add Streak to Sync Queue

**Where streak is updated with is_synced=0:**
- UserDataService (recalc, reset, grace)
- GraceSystemService (trackTaskCompletion, useGraceDay)
- EntryProvider (on save, streak recalc)

**4.4.1** Create helper in UserDataService or SyncQueueService:
```dart
static Future<void> addStreakToSyncQueue(String userId) async {
  final db = await DatabaseManager().database;
  final streak = await db.query('streaks', where: 'user_id = ?', whereArgs: [userId], limit: 1);
  if (streak.isEmpty) return;
  final row = streak.first;
  if ((row['is_synced'] as int? ?? 1) == 1) return;  // Already synced
  await LocalEntryService().addToSyncQueue(
    entityType: 'streak',
    entityId: userId,
    tableName: 'streaks',
    operation: 'upsert',
    data: {...row},  // Full streak data for Supabase
  );
}
```

**4.4.2** Call addStreakToSyncQueue after every local streak update with is_synced=0. Avoid duplicates: check if queue already has pending streak for this user_id (optional optimization).

### Step 4.7: SyncWorker — Process Sync Queue for New Entity Types

**File:** `lib/services/sync/sync_worker.dart`

**4.7.1** Extend processSyncQueue:
- Keep existing: process unsynced entries (getUnsyncedEntries).
- Add: get sync_queue items where entity_type IN ('streak', 'user_profile', 'user_settings').
- For each: call syncStreak/syncUserProfile/syncUserSettings. On success: remove from sync_queue, mark local is_synced=1. On failure: increment retry_count.

**4.7.2** Process order: entries first, then sync_queue items (streak, user_profile, user_settings). Or process sync_queue in parallel with entries — independent.

**4.7.3** Dedupe streak: if multiple streak items for same user_id, process one (merge or take latest). Simpler: one queue item per entity_type+entity_id. When adding, replace existing pending item for same entity_type+entity_id.
