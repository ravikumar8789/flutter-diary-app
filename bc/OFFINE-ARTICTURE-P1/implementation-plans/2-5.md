# Phase 2.5: Splash — If Offline → Read from SQLite Only

**Goal:** When offline at startup, splash makes zero network calls. All data comes from local SQLite. User proceeds to Home with last available data.

**Prerequisites:** Phase 1.1, 1.2, 1.3, 2.4 (connectivity check, local tables, DataFetchService reads from SQLite).

---

## 1. Offline Path Summary

| Step | Action | Network |
|------|--------|---------|
| 1 | Auth check (cached session) | No |
| 2 | Check isOnline → false | No |
| 3 | loadUserData(useLocalOnly: true) | No |
| 4 | cleanupOldEntries (local) | No |
| 5 | processSyncQueue (skips — offline) | No |
| 6 | Navigate to Home | — |

**No Supabase calls. No fetch attempts.**

---

## 2. Key Requirement: useLocalOnly Flag

When offline, we must **never** attempt Supabase. DataFetchService currently falls back to Supabase when local is empty. We need to disable that.

**Add `useLocalOnly` (or `offline`) parameter:**

| Method | When useLocalOnly: true |
|--------|-------------------------|
| fetchUserProfile | Read from local only. Return null if empty. No Supabase. |
| fetchUserSettings | Same |
| fetchEntries | Same |
| fetchEntriesWithJoins | Same |
| fetchStreaks | Same |

**Propagation:** Splash passes `useLocalOnly: true` → loadUserData(useLocalOnly: true) → UserDataService.fetchUserData(useLocalOnly: true) → DataFetchService methods(useLocalOnly: true).

---

## 3. Implementation Steps

### Step 3.1: Add useLocalOnly to DataFetchService

**File:** `lib/services/data_fetch_service.dart`

**3.1.1** Add optional param to methods used by loadUserData:
```dart
Future<Map<String, dynamic>?> fetchUserProfile(String userId, {
  bool forceRefresh = false,
  bool useLocalOnly = false,
}) async {
  final local = await _readUserProfileFromLocal(userId);
  if (useLocalOnly) return local;  // Never try Supabase
  if (!forceRefresh && local != null) return local;
  return await _fetchUserProfileFromSupabaseAndStore(userId);
}
```

**3.1.2** Same for: fetchUserSettings, fetchEntries, fetchEntriesWithJoins, fetchStreaks.

### Step 3.4: Splash Offline Branch

**File:** `lib/screens/splash_screen.dart`

**3.4.1** After `isOnline == false`:
```dart
if (!isOnline) {
  setState(() => _loadingMessage = 'Loading your journal...');
  await ref.read(userDataProvider.notifier).loadUserData(useLocalOnly: true);
  await entryService.cleanupOldEntries(retentionDays: 7);
  // Skip processSyncQueue or call it (it will no-op when offline)
  await syncWorker.processSyncQueue();  // Already checks connectivity
  // Navigate
  _navigateToHomeOrAuthBasedOnUserData();
  return;
}
```

**3.4.2** Do NOT call: calculateStreakOnAppLaunch, prefetch7DaysData, prefetchTodayData, any Supabase fetch.

### Step 3.5: Handle No Local Data (First Login Offline)

**Scenario:** User never logged in on this device, or cleared app data. Offline. No local users, user_settings, entries, streaks.

**Result:** loadUserData(useLocalOnly: true) returns success: false or userData: null (profile fetch returns null).

**Splash behavior:** Navigate to Home with error state. User sees "Setting up your journal..." or limited UI. Per base-plan: "Show Connect to load or block." For Phase 2.5, navigate to Home; user can retry when online.

**Optional:** Show message "You're offline. Connect to load your data." before navigating.

---

### Step 3.6: processSyncQueue When Offline

**File:** `lib/services/sync/sync_worker.dart`

**Current:** processSyncQueue checks _isOnline() first. If offline, returns immediately. No network call.

**Action:** No change. Call processSyncQueue in offline path — it will no-op. Keeps code path consistent.

### Step 3.7: cleanupOldEntries When Offline

**Action:** cleanupOldEntries uses local SQLite only. Safe to call. No change.

## 4. Offline Flow (Detailed)

```
Auth check → user exists
    ↓
isOnline = false
    ↓
setState('Loading your journal...')
    ↓
loadUserData(useLocalOnly: true)
  → fetchUserProfile(userId, useLocalOnly: true) → read local users
  → fetchUserSettings(userId, useLocalOnly: true) → read local user_settings
  → _fetchUserStats (from local entries, streaks)
  → Build UserData from local
    ↓
cleanupOldEntries(7)  // local only
    ↓
processSyncQueue()    // no-op, offline
    ↓
userDataState.userData != null ?
  YES → Navigate to Home
  NO  → Navigate to Home with error/empty state (limited UI)
```

## 6. Edge Cases

| Case | Handling |
|------|----------|
| First login, offline | No local data. loadUserData returns null. Navigate to Home with empty/error state. |
| Returning user, offline | Local has data from last session. loadUserData succeeds. Full app works. |
| Offline, partial local data | e.g. user exists, no settings. Return partial UserData. Handle null preferences in UI. |
| Connectivity flaky | isOnline may be false briefly. We treat as offline. User can pull-to-refresh when online. |
