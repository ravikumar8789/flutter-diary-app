# Phase 4.12: Remove Instant Sync; Use Queue Only

**Goal:** No instant/direct Supabase sync. All sync flows through the queue. User sees "Saved" immediately; sync happens when SyncWorker processes the queue (on connectivity, periodic, or after save).

**Rule:** SupabaseSyncService (batchSaveEntry, batchUpdateStreakData, etc.) is only called by SyncWorker. No `if (online) { sync(); }` patterns.

**Prerequisites:** Phase 3.7, 3.8, 3.9, 4.11. Sync queue extended; all writes local-first; SyncWorker processes all entity types.

---

## 2. Allowed Sync Triggers

| Trigger | Action | Notes |
|---------|--------|-------|
| ConnectivityService.onConnectivityChanged | processSyncQueue | When coming online |
| Splash (online path) | processSyncQueue | After startup fetches |
| EntryProvider after save | processSyncQueue | Optional; or rely on connectivity/periodic |
| App lifecycle (resume) | processSyncQueue | When app returns to foreground |
| Periodic (15 min) | processSyncQueue | Background sync |

**Key:** processSyncQueue reads from queue/unsynced entries and pushes via SupabaseSyncService. No other code calls SupabaseSyncService for writes.

## 3. Implementation Steps

### Step 3.1: EntryService — Remove All if (online) sync Blocks

**File:** `lib/services/entry_service.dart`

**3.1.1** In saveDiaryText, saveAffirmations, savePriorities, saveMeals, saveGratitude, saveSelfCare, saveShowerBath, saveTomorrowNotes:
- Remove: `if (await _isOnline()) { _syncService.syncEntry(...); syncAffirmations(...); }` etc.
- Keep: local save only (`_localService.upsert*`).
- LocalEntryService already adds to sync_queue on upsert. SyncWorker will process.

**3.1.2** Remove `_isOnline` if no longer used. Or keep for read-only fetches (e.g. fetchEntryFromCloud).

---

### Step 3.2: EntryProvider — Remove batchSaveEntry, batchUpdateStreakData

**File:** `lib/providers/entry_provider.dart`

**3.2.1** (From 3-8) Remove batchSaveEntry. After _savePendingChangesToLocal, call processSyncQueue (or skip; connectivity/periodic will handle).
**3.2.2** (From 4-11) Remove batchUpdateStreakData in _checkGapsAndRecalculateStreak. Use addStreakToSyncQueue.

---

### Step 3.3: UserDataService — Remove All batchUpdateStreakData

**File:** `lib/services/user_data_service.dart`

**3.3.1** Replace _scheduleStreakSync with addStreakToSyncQueue (4-11).
**3.3.2** Remove batchUpdateStreakData in calculateStreakOnAppLaunch (lines ~1073, 1200, 1272). Use addStreakToSyncQueue after local update.
**3.3.3** Remove users.insert; use local + addToSyncQueue (3-8).

---

### Step 3.4: GraceSystemService — Remove batchUpdateStreakData

**File:** `lib/services/grace_system_service.dart`

**3.4.1** In trackTaskCompletion (or equivalent), remove `await _syncService.batchUpdateStreakData(...)`.
**3.4.2** After local streak/habits update with is_synced=0, add `UserDataService.addStreakToSyncQueue(userId)`.

---

### Step 3.5: UserPreferenceSyncService — Local + Queue

**File:** `lib/services/user_preference_sync_service.dart`

**3.5.1** syncNotificationSettingsToCloud: write to local user_settings, addToSyncQueue(entity_type='user_settings').
**3.5.2** syncAppearanceToCloud: write to local user_profiles (or users), addToSyncQueue(entity_type='user_profile').
**3.5.3** No direct Supabase. Callers unchanged; they call the same method, which now does local + queue.

---

### Step 3.6: Do NOT Trigger processSyncQueue Excessively

**3.6.1** After entry save: optionally call processSyncQueue once. Avoid calling it in a tight loop.
**3.6.2** Prefer: connectivity + periodic + splash. Optional: single processSyncQueue after batch save.
**3.6.3** "Instant" from user POV: "Saved" shows immediately. Sync can happen seconds later via processSyncQueue. No need to block.
