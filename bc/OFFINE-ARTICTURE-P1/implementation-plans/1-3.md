# Phase 1.3: Refactor DataFetchService to Read from SQLite

**Goal:** DataFetchService reads from local SQLite first. Supabase fetch kept for startup refresh (fetch → store → then app reads local).

**Prerequisites:** Phase 1.1 (users, user_settings tables), Phase 1.2 (DataRepository removed, DataFetchService unwrapped — no _repository).

---

## 1. Read Strategy

| Method | Primary Source | Fallback | Startup Refresh |
|--------|----------------|----------|-----------------|
| fetchUserProfile | Local `users` | Supabase → store → return | Yes |
| fetchUserSettings | Local `user_settings` | Supabase → store → return | Yes |
| fetchEntries | Local `entries` | Supabase → store → return | Yes |
| fetchEntriesWithJoins | Local (entries + related) | Supabase → store → return | Yes |
| fetchEntryByDate | Local `entries` | Supabase → store → return | Via prefetch |
| fetchStreaks | Local `streaks` | Already has logic | Yes |

**Out of scope (keep Supabase only for now):** fetchEntriesByMoodWithJoins, fetchEntriesWithSelect, fetchMonthMetadata, fetchMonthlyAnalytics, fetchWeeklyAnalytics, fetchEntryInsights, fetchAllHabitsDaily — History/Analytics, handled later.

---

## 2. Method Signature Pattern

Add optional `forceRefresh` parameter where startup needs fresh data:

```dart
Future<Map<String, dynamic>?> fetchUserProfile(String userId, {bool forceRefresh = false}) async {
  if (!forceRefresh) {
    final local = await _readUserProfileFromLocal(userId);
    if (local != null) return local;
  }
  // Fetch from Supabase, store in local, return
  return await _fetchUserProfileFromSupabaseAndStore(userId);
}
```

**Startup calls:** `fetchUserProfile(userId, forceRefresh: true)` — always fetches fresh.

**Normal reads:** `fetchUserProfile(userId)` — reads local first.

## 3. Implementation Steps

### Step 3.1: Add Local Read Helpers

**File:** `lib/services/data_fetch_service.dart`

**3.1.1** `_readUserProfileFromLocal(String userId)` → `Map<String, dynamic>?`
- Query `users` where id = userId
- Convert SQLite row to Supabase-like map (column names: id, email, display_name, etc.)
- Return null if empty

**3.1.2** `_readUserSettingsFromLocal(String userId)` → `Map<String, dynamic>?`
- Query `user_settings` where user_id = userId
- Convert: reminder_days TEXT → parse JSON to List
- Return null if empty

**3.1.3** `_readEntriesFromLocal(userId, startDate, endDate)` → `List<Entry>`
- Query `entries` where user_id, entry_date between
- Map rows to Entry.fromJson()
- Return list

**3.1.4** `_readEntriesWithJoinsFromLocal(userId, startDate, endDate)` → `List<Map<String, dynamic>>`
- Query entries for date range
- For each entry: query entry_affirmations, entry_priorities, entry_meals, entry_gratitude, entry_self_care, entry_shower_bath, entry_tomorrow_notes by entry_id
- Build joined map: `{...entry, entry_affirmations: {...}, entry_meals: {...}, ...}`
- Match Supabase nested format for compatibility with _storeEntriesWithRelatedData consumers

**3.1.5** `_readEntryByDateFromLocal(userId, date)` → `Entry?`
- Query entries where user_id and entry_date
- Return Entry.fromJson() or null

---

### Step 3.2: Add Supabase Fetch + Store Helpers

**3.2.1** `_fetchUserProfileFromSupabaseAndStore(String userId)` → `Map<String, dynamic>?`
- Fetch from Supabase `users` table
- If not null: insert/replace into local `users`, set is_synced=1, last_sync_at=now
- Return response

**3.2.2** `_fetchUserSettingsFromSupabaseAndStore(String userId)` → `Map<String, dynamic>?`
- Fetch from Supabase `user_settings`
- If not null: insert/replace into local `user_settings`, set updated_at, is_synced, last_sync_at
- reminder_days: store as JSON string
- Return response

**3.2.3** `_fetchEntriesFromSupabaseAndStore(userId, startDate, endDate)` → `List<Entry>`
- Fetch from Supabase entries
- For each: insert/replace into local `entries` (mark is_synced=1)
- Return entries

**3.2.4** `_fetchEntriesWithJoinsFromSupabaseAndStore(...)` → `List<Map<String, dynamic>>`
- Fetch from Supabase with joins
- Call DataPrefetchService._storeEntriesWithRelatedData (or inline logic) to store
- Return response

### Step 3.4: Column Name Mapping (Local → Supabase-like)

Local `users` uses same names. Supabase returns: id, email, email_verified, display_name, avatar_url, locale, timezone, marketing_opt_in, created_at, updated_at. Local has is_synced, last_sync_at. For consumers expecting Supabase format, return map with standard names. email_verified: local INTEGER 0/1 → map as boolean.

Local `user_settings`: reminder_days TEXT "[1,2,3,4,5,6,7]" → parse to List for map. Supabase expects array; some consumers may expect List.

## 4. Local Joined Entry Structure

To build `List<Map<String, dynamic>>` from local (same as Supabase response):

```dart
// Pseudocode
for (entryRow in entriesRows) {
  final entryId = entryRow['id'];
  final affirmations = await db.query('entry_affirmations', where: 'entry_id = ?', whereArgs: [entryId]);
  final meals = await db.query('entry_meals', ...);
  // ... etc
  final map = {
    ...entryRow, // id, user_id, entry_date, diary_text, mood_score, tags, created_at, updated_at
    'entry_affirmations': affirmations.isNotEmpty ? _rowToSupabaseFormat(affirmations.first) : null,
    'entry_meals': meals.isNotEmpty ? _rowToSupabaseFormat(meals.first) : null,
    // ...
  };
  result.add(map);
}
```

Supabase format uses snake_case. Local uses snake_case. entry_affirmations.affirmations is JSON string in local → keep as string or parse to List for compatibility. Check EntryAffirmations.fromSupabaseJson — it expects affirmations as List. So we need to parse the JSON string when building the map.

## 9. Edge Cases

- **Local users table empty (first install):** forceRefresh at startup fetches and stores. Normal read returns null until startup completes.
- **Offline at startup:** forceRefresh tries Supabase, fails. Startup should catch and proceed with empty local. App shows empty/placeholder until online.
- **reminder_days format:** Supabase returns `[1,2,3,4,5,6,7]`. Local stores `"[1,2,3,4,5,6,7]"`. When reading, parse JSON. When storing from Supabase, store as JSON string.
