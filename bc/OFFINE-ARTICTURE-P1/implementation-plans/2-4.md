# Phase 2.4: Splash — Check Online → 3 Fetches → Store in SQLite

**Goal:** Splash checks connectivity. If online: 3 parallel fetches with timestamp merge, store in SQLite. If offline: read local only. Reduce startup to 3 calls, faster splash.

**Prerequisites:** Phase 1.1, 1.2, 1.3 complete (local tables, no cache, DataFetchService reads from SQLite).

---

## 1. Flow Overview

```
Auth check (unchanged)
    ↓
Check online (ConnectivityService + InternetAddress.lookup)
    ↓
┌─────────────────────────────────────────────────────────────┐
│ OFFLINE                        │ ONLINE                      │
├─────────────────────────────────────────────────────────────┤
│ • Read from local only         │ • 3 parallel fetches         │
│ • loadUserData (reads local)  │ • Merge by timestamp         │
│ • Skip prefetch                │ • Store in SQLite            │
│ • processSyncQueue (no-op)    │ • loadUserData (reads local) │
│ • Navigate to Home             │ • processSyncQueue (push)   │
│                                │ • Navigate to Home           │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. The 3 Fetches (Online Only)

| # | Fetch | Supabase Source | Store In | Timestamp Compare |
|---|-------|-----------------|----------|-------------------|
| 1 | User profile + settings | `users`, `user_settings` (2 calls) | `users`, `user_settings` | users: updated_at; user_settings: no updated_at in Supabase — always store when fetched |
| 2 | Entries (7-day or today) | `entries` + joins | `entries`, `entry_*` tables | Per-entry: Supabase.updated_at vs local.updated_at |
| 3 | Streak | `streaks` | `streaks` | Supabase.updated_at vs local.last_sync_at |

**Fetch 1:** 2 calls (users + user_settings) — run in parallel. Can combine via RPC later.

**Fetch 2:** 7-day or today based on `DataSyncFlagService.needsDataFetch()`:
- `needsFetch == true` → fetch 7 days
- `needsFetch == false` → fetch today only

---

## 3. Timestamp Merge Logic (Per Entity)

**Rule:** Only overwrite local when `Supabase.updated_at > local.last_sync_at` (or `local.updated_at` for entries).

| Entity | Compare | Action if Supabase newer |
|--------|---------|--------------------------|
| users | response.updated_at vs local.last_sync_at | Overwrite local |
| user_settings | No updated_at in Supabase | Always store when fetched (fresh) |
| entries | Per row: response.updated_at vs local.updated_at | Overwrite that row |
| streaks | response.updated_at vs local.last_sync_at | Overwrite, run streak calc |

**If local newer:** Keep local. Do not overwrite. (Local changes are in sync queue or will be.)

### Step 5.5: Parallel Fetch Execution

```dart
if (isOnline) {
  setState(() => _loadingMessage = 'Syncing your journal...');
  
  final needsFetch = await DataSyncFlagService.needsDataFetch();
  final now = DateTime.now();
  final today = DateTime(now.year, now.month, now.day);
  final weekStart = today.subtract(const Duration(days: 6));
  
  await Future.wait([
    fetchAndMergeUserProfile(userId),
    fetchAndMergeUserSettings(userId),
    needsFetch
        ? fetchAndMergeEntriesWithJoins(userId, weekStart, today)
        : fetchAndMergeEntriesWithJoins(userId, today, today),
    fetchAndMergeStreaks(userId),
  ]);
  
  if (needsFetch) await DataSyncFlagService.clearNeedsDataFetch();
}
```

## 7. ConnectivityService.isOnline Enhancement

**Current:** `Connectivity().checkConnectivity()` only.

**Enhancement:** Add `InternetAddress.lookup('google.com')` for robustness (like SyncWorker). Some networks report "connected" but have no internet.

```dart
Future<bool> isOnline() async {
  try {
    final results = await Connectivity().checkConnectivity();
    if (results.any((r) => r == ConnectivityResult.none)) return false;
    final result = await InternetAddress.lookup('google.com');
    return result.isNotEmpty && result[0].rawAddress.isNotEmpty;
  } catch (_) => false;
}
```
